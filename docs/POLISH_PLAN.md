# แผนเก็บงาน Anime Worlds

เป้าหมายคือทำให้แต่ละโลกมีการโต้ตอบเฉพาะเรื่อง ภาพคมตามความละเอียดต้นฉบับ และใช้งานได้ครบทั้งเมาส์ คีย์บอร์ด และมือถือ ภาพปัจจุบันเป็นฉาก 2D ที่ซ้อนอนุภาค 3D; โมเดลตัวละครและเมืองที่เดินสำรวจได้ยังเป็นงานระยะถัดไป

## P0 — แก้ความถูกต้องก่อน

- [x] Hotspot มีเครื่องหมายให้เห็น ผูกกับพิกัดภาพจริง และเลื่อนตามการครอป/parallax
- [x] จุดที่อยู่นอกกรอบภาพบนมือถือยังเข้าถึงได้จากสมุดสำรวจ
- [x] ล้างข้อความ/เอฟเฟกต์เมื่อเปลี่ยนโลก ไม่ปล่อยข้อมูลเรื่องก่อนค้างอยู่
- [x] โหลดภาพผิดพลาดหรือ timeout แล้วกลับฮับพร้อมข้อความที่ลองใหม่ได้
- [x] Escape/ปุ่ม Home ยกเลิกการโหลดได้ ไม่มี async callback เปิดโลกเก่าทับหน้าใหม่
- [x] การ์ดที่ซ่อนอยู่ไม่รับ Tab; จัด focus หลังเข้า/ออกโลกและปิด dialog
- [x] Reduced motion หยุด shader/parallax และปรับเอฟเฟกต์เป็นการตอบสนองแบบนิ่ง
- [x] คืน geometry/material ของเอฟเฟกต์และโลกที่เลิกใช้

## เกณฑ์ส่งมอบ

- Production build ผ่าน
- เข้าโลก 3 โลก ใช้ action และอ่านจุดสำรวจได้ครบทุกโลก
- ตรวจ desktop 1440×900, mobile 390×844 และจอแนวนอนความสูงน้อย
- จำลองภาพโหลดไม่สำเร็จและกด Escape ระหว่างโหลด แล้วกลับฮับและเข้าใหม่ได้
- ตรวจ keyboard focus, dialog Escape, cinematic Escape และ reduced motion
- ไม่พบ runtime exception หรือ resource ที่ขาดใน flow ปกติ
- Commit/push branch work และตรวจ SHA บน remote

## P2 — แผนต่อยอดหลังรอบนี้

1. แยก artwork เป็น foreground/midground/sky พร้อม depth map เพื่อให้ parallax มีมิติจริง กำหนด camera bounds ให้ภาพไม่เผยขอบ
2. One Piece: เรือ GLB มีใบเรือขยับและน้ำ shader; Demon Slayer: โทริอิ/โคมไฟ/กิ่งวิสทีเรีย GLB พร้อม fog; Attack on Titan: โมดูลกำแพง/หลังคาเมืองและเส้นทางกล้อง ODM
3. นำเข้าโมเดลที่ตรวจที่มาและสิทธิ์ได้ จัดทำ asset manifest พร้อมผู้สร้าง URL ใบอนุญาต ขนาด และงบ draw calls ก่อนเลือกไฟล์จริง
4. เพิ่ม ambient audio แยกโลกและ spatial sound ด้วยไฟล์ที่มีสิทธิ์ พร้อม mute ที่จำค่าได้
5. ทดสอบ FPS/หน่วยความจำบนอุปกรณ์จริง แล้วเลือก LOD, texture compression และ adaptive quality จากข้อมูลวัด

P2 เป็นขอบเขตถัดไป ยังไม่ถือว่าทำเสร็จจากการแสดงภาพประกอบเพียงอย่างเดียว

### งานรายโลกใน P2 และเกณฑ์รับงาน

| โลก | สิ่งที่ต้องเตรียม | ลูกเล่นถัดไป | เกณฑ์รับงาน |
| --- | --- | --- | --- |
| One Piece | เรือ GLB แยก hull/sail/rope, normal map น้ำ, sky layer | กล้องสำรวจดาดฟ้า, ลมปรับใบเรือ, คลื่นตอบสนองตามลม | กล้องไม่ทะลุตัวเรือ, ใบเรือกับคลื่นตอบสนองไปทิศเดียวกัน, ปุ่มกลับใช้ได้ทุกมุม |
| Demon Slayer | โทริอิ/โคมไฟ/กิ่งวิสทีเรียแบบ instancing, ฉากท้องฟ้าแยก | ทางเดินชมป่า, โคมไฟตอบสนอง, เส้นสายน้ำตามการลากนิ้ว | ไม่เดินทะลุประตู/ต้นไม้, ใบไม้ไม่บดบังทางทั้งหมด, touch และเมาส์ใช้เส้นสายน้ำได้เหมือนกัน |
| Attack on Titan | กำแพงและหลังคาแบบโมดูล, วัสดุหิน, ไททันระยะไกล | เส้นทางกล้อง ODM แบบกำหนด, เลือกจุดยิงพลุ, สัญญาณตอบรับ | เส้นทางกล้องไม่ชนอาคาร, ออกจาก cinematic ได้ทันที, ลดกล้องเคลื่อนไหวเมื่อใช้ reduced motion |

เริ่มด้วย asset review และหนึ่งฉากทดลองต่อโลก แล้ววัดก่อนขยาย โดยตั้งงบเบื้องต้นต่อโลกไม่เกิน 8 MB ของไฟล์ดาวน์โหลด ใช้ texture 2K desktop/1K mobile และบีบ GLB/KTX2 เมื่อ pipeline พร้อม ตัวเลขนี้เป็นเป้าหมายสำหรับตรวจงาน ไม่ใช่ผล benchmark ปัจจุบัน


## ผลตรวจรอบนี้

- `npm run build` ผ่าน
- `APP_URL=http://127.0.0.1:4174 npm run test:browser` ผ่านกับ production preview
- ตรวจทั้งสามโลก, action/cooldown, marker, สมุดสำรวจ, focus, cinematic, progress หลัง reload, touch, retina, แนวนอน และ reduced motion
- ทดสอบภาพโหลดผิดพลาด, ยกเลิกระหว่างโหลด, timeout 10 วินาที และ retry สำเร็จ; response ที่มาช้าไม่เปิดโลกที่ยกเลิกกลับมา
- ภาพส่งมอบอยู่ใน `docs/screenshots/` และมีภาพขณะใช้ action แยกทั้งสามโลก
- ยังไม่มีผลวัด FPS หรือ memory บนอุปกรณ์จริง; ไม่ใช้ผล headless แทน benchmark อุปกรณ์
